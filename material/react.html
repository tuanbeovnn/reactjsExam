Elements and components

JSX

  • A recommended syntax extension to JavaScript
  • Describes how the UI should look like
  • Produces React "elements" where markup and logic are not separated in different files
    • Instead, React separates concerns with loosely coupled units called “components” that contain both

JSX Pros

Even if React does not require using JSX, but most people find it helpful as a visual aid when working with UI. It also allows React to show more useful error and warning messages.
https://reactjs.org/docs/introducing-jsx.html 

          const element = 
          ( <h1 className="greeting"> Hello, world! </h1> );

JSX

  • Embed expressions with curly braces
  • Use quotes to specify string literals as attributes
  • Empty tags may be closed XML style with />
  • JSX tags may contain children
  • JSX escapes embedded values

JSX is compiled to React.createElement() calls. This results in objects (these are equivalent):


            const element = (
Hello, world!
);
            const element = React.createElement('h1',{className: 'greeting'}, 'Hello, world!');
https://reactjs.org/docs/introducing-jsx.html

Elements and rendering

Smallest building block in React, e.g.: 

            const element = 
Hello, world
;
To render this, you need a <div> in your HTML file
You can then render like this 

              const root = ReactDOM.createRoot(
                document.getElementById('root')
              );
              root.render(element);

Updates when necessary

  • React DOM compares the element and its children to the previous one
  • Only applies the DOM updates necessary to bring the DOM to the desired state
  • root.render() is usually called only once

Components

  • UI splits: independent, reusable pieces, and think about each piece in isolation
  • Like JavaScript functions, but can be also classes
    • classes have some additional features compared to functions
    • Hooks have been later implemented to enable better use of functions
  • Accept arbitrary inputs, called "props"
  • Return React elements describing what should appear on the screen
  • "props" are passed as an argument to function components (more on these later)
  • Components always start with capital letters
  • Components can refer to other components in their output
  • In React, buttons, forms, dialogs, etc. are commonly expressed as components.

Rendering components

You start by composing the components, e.g.

                  <Welcome name="Sara" />
                  <Welcome name="Cahal" />

  • Are the input that components take in
  • Are used in function and class components

  • Are read-only
    • You are not allowed to change the values of inputs in components
      • This will result in e.g. passing functions as props

State

  • State is similar to props, but it is private and fully controlled by the component.
  • Updated using setState (when creating Class based components!)
    • merges changes
  • Not to be modified directly
  • Use: 
    
              this.setState({comment: 'Hello'});
  • Updates may be asynchronous and may be combined
  • Don’t rely on existing state values when setting new states
  • Pass a function to setState instead:
    • 
              this.setState((state, props) => 
              ({ counter: state.counter + props.increment }));

Lifecycle methods

  • The componentDidMount()method runs after the component output has been rendered to the DOM
  • componentWillUnmount() is called when a component is removed from the DOM
  • componentDidUpdate() is invoked immediately after updating occurs, not for the initial render

componentDidMount() {
  this.timerID = setInterval( 
  () => this.tick(), 
  1000 );
}
             

tick() {
  this.setState({
  date: new Date()
  });
}
            

componentWillUnmount() {
  clearInterval(this.timerID);
}

Data flow

  • Data flows down
  • Pass data as props to child components
  • Parent components do not see the state of a child
  • Child components do not know details about the prop data.
    • e.g. if it came from the parent's state or props etc.

Events

  • Similar to DOM element events
  • Named using camelCase
  • No need to use addEventListner to DOM elements
  • A common pattern is for an event handler to be a method on the class
  • A function is passed as the event handler
Handling Events

Event example

this will be undefined when a callback is actually called, if not bound 

            class Toggle extends React.Component {
              constructor(props) {
                super(props);
                this.state = {isToggleOn: true};
            
                // This binding is necessary to make `this` work in the callback
                this.handleClick = this.handleClick.bind(this);
              }
            
              handleClick() {
                this.setState(prevState => ({
                  isToggleOn: !prevState.isToggleOn
                }));
              }
            
              render() {
                return (
                  <button onClick={this.handleClick}>
                    {this.state.isToggleOn ? 'ON' : 'OFF'}
                  </button>
                );
              }
            }

Event handler arguments

  • e is the event (used to prevent default action here)
    • 
              function Form() {
                function handleSubmit(e) {
                  e.preventDefault();
                  console.log('You clicked submit.');
                }
                return (
                  <form onSubmit={handleSubmit}>
                    <button type="submit">Submit</button>
                  </form>
                );
              }
  • Arguments are passed like this (e will be passed as the second argument with both approaches):

            <button onClick={(e) => this.deleteRow(id, e)}>Delete Row</button>
            //or
            <button onClick={this.deleteRow.bind(this, id)}>Delete Row</button>

Lists and keys

  • "key" is a special string attribute you need to include when creating lists of elements.
  • Keys help React identify which items have changed, are added, or are removed.
  • Keys must be unique among siblings.
    • 
            function NumberList(props) {
              const numbers = props.numbers;
              const listItems = numbers.map((number) =>
                <li key={number.toString()}>
                  {number}
                </li>
              );
              return (
                <ul>{listItems}</ul>
              );
            }
            const numbers = [1, 2, 3, 4, 5];
            const root = ReactDOM.createRoot(document.getElementById('root'));
            root.render(<NumberList numbers={numbers} />);
  • Best is to use unique stable keys, e.g., item indices work if absolutely necessary:
    •

Hooks

  • An addition with React 16.8 that allows the use of state and other React features without using classes
  • Optional (but now recommended)
    • This actually makes everything simpler!
      • Why?
      • The use of “this” has been confusing with classes
      • Code reuse and code organisation easier is made easier
      • Reuse stateful logic without changing component hierarchy
      • Split components into smaller functions
    • Do more without classes!
      • Embrace functions, but do not require you to go completely functional.
    https://reactjs.org/docs/hooks-intro.html

Using the State Hook



            import React, { useState } from 'react';

            function Example() {
              // Declare a new state variable, which we'll call "count"
              const [count, setCount] = useState(0);
            
              return (
                <div>
                  <p>You clicked {count} times</p>
                  <button onClick={() => setCount(count + 1)}>
                    Click me
                  </button>
                </div>
              );
            }

Using the State Hook

  • useState lets you add React state to function components
  • Calling useState
    • Declares a "state variable" that can be named
    • Provides the functionality provided by this.state in classes
  • useState argument
    • Is the initial state
    • Does not need to be a class
  • useState returns
    • A pair of values
      • Current state
      • Function that updates it

Using the State Hook

  • Reading state
    • Use the variable directly
  • Updating state
    • Use the function that updates it, e.g.
      • setCount(count + 1)
  • You can use more than one state variable
    • Give different names
  • Updates
    • Always replace, never merge

Using The Effect Hook

  • Instruct to do something after render
  • Instead of
    • componentDidMount
    • componentDidUpdate
    • componentWillUnmount
  • Perform side effects in functional components
  • Call from within a component

          import React, { useState, useEffect } from 'react';

          function Example() {
            const [count, setCount] = useState(0);

            useEffect(() => {
              document.title = `You clicked ${count} times`;
            });

            return (
              <div>
                <p>You clicked {count} times</p>
                <button onClick={() => setCount(count + 1)}>
                  Click me
                </button>
              </div>
            );
          }

Clean up on unmount

  • If you need to do clean up (e.g., unsubscribe from something)
    • Return a function where you clean up
      • Executed on unmount but also before running the effect again
  • You can have multiple separate effects
  • For performance reasons, it is possible to specify effects to only run if certain variables have changed

            useEffect(() => {
              function handleStatusChange(status) {
                setIsOnline(status.isOnline);
              }
              ChatAPI.subscribeToFriendStatus(props.friend.id,
                handleStatusChange);
              // Specify how to clean up after this effect:
              return function cleanup() {
                ChatAPI.unsubscribeFromFriendStatus(props.friend.id,
                  handleStatusChange);
              };
            });

Hook rules

In order for hooks to work smoothly, there are two rules you need to follow

  • Only call hooks on the top level
    • Not inside loops, conditions or nested functions!
    • Hooks need to be called in the same order each time a component renders
  • Only call hooks from React functions
    • Not from Javascript functions
    • Yes from React function components
    • Yes from custom Hooks

The eslint-plugin-react-hooks (included by default in Create React App) enforces these rules

Custom Hooks

  • Javascript function that starts with “use”
  • May call other hooks
  • Not a React component
    • You decide what arguments it takes and what it returns
  • Why?
    • Remove duplicate logic from components
  • Use it by just calling it, e.g., 
    const isOnline = useFriendStatus(props.friend.id);
